# Dark Factory — мультиагентная система управления производством дизельного топлива

Прототип автономного управления цепочкой **АВТ → гидроочистка 24-2000 → блендинг**.
Система получает состояние процесса, оценивает риск выхода за спецификацию,
сравнивает допустимые варианты режима, выбирает один и объясняет выбор оператору.
Если надёжной рекомендации нет — прямо об этом говорит.

---

## Быстрый старт за три команды

```bash
pip install -r requirements.txt
make all                 # витрина → модели → отчёты → сценарии → дашборд (~3 мин)
open artifacts/dashboard.html
```

Через Docker (сборка без обращения к внешним сервисам во время работы):

```bash
docker compose run --rm dfmas all
```

Один цикл принятия решения на конкретном моменте истории:

```bash
python -m dfmas.cli run --at "2025-11-20 14:00"
```

> Положите `data_1.rar` в корень проекта, а три xlsx из пакета — в `data/raw/`
> под именами `LIMS.xlsx`, `PAK.xlsx`, `tags_reference.xlsx`.
> `make data` распакует архив сам.

## Четыре решения, которые отличают это решение от типового

### 1. Витрина «на момент времени»: утечка невозможна конструктивно

Каждое значение качества несёт **две метки времени**: момент отбора пробы и
момент, когда результат физически мог стать известен оператору. Для ЛИМС это
отбор + 4 часа (подтверждено экспертом), для ПАК — +10 минут.

Единственный способ получить данные внутри системы — `AsOfStore.snapshot(t)`,
который фильтрует по `available_at <= t`. Агенты **не имеют доступа к полным
таблицам**, поэтому заглянуть в будущее нельзя даже случайно. Обращение к
будущему существует ровно в одном месте — методе с говорящим именем
`future_value()`, который используется только в офлайн-оценке.

Бэктест и онлайн используют один и тот же код, поэтому поведение совпадает
по построению. Свойство закреплено тестами: [`tests/test_no_leakage.py`](tests/test_no_leakage.py).

### 2. Мы проверили справочник и нашли в нём ошибку

В листе «КИП» в описании тега **F22 склеены два описания** — из-за этого часть
строк сдвинута относительно тегов. Видно по дубликатам: «Расход бензина
c установки» стоит у F1 и T12, «Расход ГО ДТ в цех №8» — у F17 и T23.

Проверка по данным подтверждает: описания приписывают серу тегам T6, W7 и P13,
но корреляция каждого из них с лабораторной серой **равна нулю**. Единственный
тег, который ведёт себя как содержание серы, — **Q21** (совпадает с прямым
ответом эксперта). Ещё одна находка: теги T5, T6, T11, T12, T23, P13 взаимно
коллинеарны с корреляцией до 0.998 — подавать их в модель как независимые
управляющие переменные нельзя.

Подробности и таблицы: [`reports/01_tag_audit.md`](reports/01_tag_audit.md).

### 3. Мы говорим, чего на этих данных сделать нельзя

| предиктор лабораторной серы | MAE, мг/кг | ROC-AUC события «> 10 мг/кг» |
|---|---|---|
| константа (медиана обучающей выборки) | 1.32 | 0.50 |
| поточный анализатор в тот же момент | **1.10** | **0.73** |
| поточный анализатор за 2 ч до отбора | 1.50 | 0.59 |
| гребневая регрессия по всем 96 тегам | 1.63 | 0.71 |
| градиентный бустинг по всем тегам | 1.97 | переобучение, R² < 0 |

**Добавление 96 технологических тегов не улучшает ничего.** Причина физическая:
расхождение пары «лаборатория — поточный анализатор» (σ ≈ 1.0 мг/кг) сопоставимо
с движением самого процесса за горизонт прогноза (σ ≈ 1.1 мг/кг). Примерно
половина разброса, который видит оператор, вообще не связана с режимом установки.

Отсюда три архитектурных решения:

1. **уровень берётся из измерения**, а не из модели: прогноз = факт + приращение;
2. **приращение считает кинетика гидрообессеривания** — монотонная по построению
   и корректно экстраполирующая за пределы наблюдавшегося режима;
3. **продуктом является калиброванный риск с интервалом**, а не точка.

Система показывает оператору **разложение риска** на технологическую и
измерительную части. Поднимать температуру, чтобы компенсировать расхождение
двух приборов, бессмысленно — и система об этом прямо пишет.

### 4. Виртуальные анализаторы с онлайн-коррекцией по лаборатории

Формулы листа «ВАК» реализованы ровно в том виде, в каком их **исправил эксперт**.
Поверх формулы работает EWMA-коррекция смещения, обновляемая только в моменты
`available_at` лабораторных результатов. Это численная реализация правила ТЗ
«ЛИМС → ПАК → ВАК».

Результат на отложенном по времени периоде — MAE в единицах показателя:

| ВАК | сырая формула | постоянная поправка | **онлайн-коррекция** |
|---|---|---|---|
| Т90 | 11.14 | 5.19 | **4.47** |
| Т50 | 5.95 | 5.06 | **2.93** |
| Отгон до 250 °C | 4.59 | 3.54 | **2.17** |
| Плотность D15 | 2.72 | 2.03 | **1.34** |
| Температура помутнения | 4.56 | 1.71 | **0.91** |
| ПТФ | 11.55 | 1.66 | **1.60** |

Подробности: [`reports/02_va_validation.md`](reports/02_va_validation.md).

## Как принимается решение

Оркестратор проходит ровно последовательность из раздела 1 ТЗ. Ключевое —
**два уровня отсева**, которые делают экономику неспособной перевесить качество:

* **Уровень 1 — допустимость.** Вариант отбрасывается, если точечный прогноз
  выходит за жёсткий предел или его запретил агент надёжности.
* **Уровень 2 — соответствие.** Среди допустимых выделяются те, у которых
  вероятность нарушения не выше 10 %.

Отсев выполняется **до** сравнения по экономике. Среди прошедших максимизируется
маржа — и только тогда, когда качество уже обеспечено.

Шесть возможных исходов:

| Решение | Когда | Что видит оператор |
|---|---|---|
| `hold` | запас достаточен | «вмешательство не требуется» |
| `act` | есть допустимое улучшение | конкретные теги и уставки |
| `act_best_effort` | порога риска достичь нельзя | режим минимального риска + прямое предупреждение |
| `hold_best_effort` | то же, но действие не помогает | почему бездействие лучше |
| `act_recovery` | спецификация **уже** нарушена | план вывода в норму |
| `refuse` | данные непригодны или надёжность запретила всё | причина отказа |

Умение отказаться прямо названо в ТЗ частью качественного решения. В бэктесте
отказ выдан в 9.7 % циклов и **всегда** с названной причиной.

## Сценарии: результат меняется вслед за данными

Эксперт потребовал, чтобы сценарии не были «жёсткими». Поэтому сценарий у нас —
это **подмена входов над реальным историческим срезом**, а не записанный ответ:
те же агенты, те же модели, другие данные.

```bash
python -m dfmas.cli scenario --all
python -m dfmas.cli scenario feed_sulfur_up
```

| Сценарий | Проверяет |
|---|---|
| `steady` | нет ложных срабатываний на устойчивом режиме |
| `feed_sulfur_up` | сценарий эксперта: утяжелилось сырьё, запас есть → система не дёргает установку, но считает требуемую компенсацию |
| `feed_sulfur_up_tight` | то же утяжеление, запаса нет → требуется повышение температуры |
| `cost_relax` | есть запас → **снизить** температуру и сэкономить (оптимизация работает в обе стороны) |
| `winter_grade` | смена задания на качество меняет рецептуру и её цену |
| `stale_lab` | устаревшие и неполные данные → корректный отказ |
| `sensor_conflict` | два анализатора серы разошлись → блокировка цикла |
| `severe_regime` | конфликт качества и надёжности: повышение температуры запрещено, ищется обходной путь |
| `blend_cetane` | дефицит цетанового числа → минимальная дозировка присадки |
| `blend_infeasible` | допустимой рецептуры нет → честный отказ, а не «наименее плохая» смесь |

Сценарии описаны в [`config/scenarios.yaml`](config/scenarios.yaml) — **меняйте
любое поле и получайте другой расчёт**.

### Доказательство «мягкости»

```bash
python -m dfmas.cli sweep --at "2024-04-26 20:00:00"
```

Один момент времени, одни агенты, меняется только сера сырья:

| сера сырья, % масс. | решение | ΔT реактора, °C | прогноз серы при бездействии | требуемая компенсация, °C |
|---|---|---|---|---|
| 0.70 | act | −2.65 | 5.70 | −7.89 |
| 1.00 | act | −2.65 | 6.64 | −2.40 |
| 1.30 | act | −2.65 | 7.58 | +2.36 |
| 1.45 | hold_best_effort | 0.00 | 8.04 | +4.53 |
| 1.80 | act_best_effort | +2.65 | 9.12 | +9.14 |

Прогноз растёт монотонно, требуемая компенсация меняет знак — от «снизить
температуру и сэкономить» до «поднять, иначе нарушим норматив».

## Воспроизводимость

Эксперт: *«При одинаковом состоянии системы должны воспроизводиться значимые
результаты… главное — одно и то же решение и одинаковые численные результаты»*.

У нас совпадает и **текст рекомендации**: он собирается детерминированно из
шаблонов по числовым результатам агентов. Ни одного генеративного элемента.

Как это обеспечено:

* система **не хранит состояния между циклами** — всё приходит из среза и из
  предобученного `model_bundle.json`;
* единственный источник случайности — зерно `SEED` в [`config.py`](src/dfmas/config.py);
* каждая рекомендация несёт **отпечаток состояния** (`state_hash`);
* все пороги, веса, цены и спецификации вынесены в [`config/*.yaml`](config/) —
  в коде нет ни одной магической константы, влияющей на решение;
* свойство закреплено тестами: [`tests/test_determinism.py`](tests/test_determinism.py).

```bash
make test        # 43 теста: утечка, детерминизм, ограничения, кинетика, сценарии
```

Развёртывание в периметре: чистый Python, зависимости из стандартного PyPI,
Docker-образ не обращается к внешним сервисам во время работы, дашборд — один
HTML-файл без внешних запросов. Ограничений, мешающих работе на Astra Linux
или РЕД ОС, нет.

## Допущения — все явные

Каждое допущение помечено в конфигурации меткой `[ДОП]` и имеет обоснование.
Главные:

| Допущение | Обоснование |
|---|---|
| Кинетика ГДС: порядок 1.5, Ea = 105 кДж/моль, торможение H2S | литературные значения; результат (−5.9 %/°C) перекрёстно проверен идентификацией по истории (−3.5 %/ед. тега) |
| Коридор изменения MV за 30 мин | 95-й процентиль фактической скорости изменения в истории; **исторический размах не выдаётся за промышленный предел** |
| Экономические цены | фактических данных нет, ТЗ разрешает прокси; задано экспертом только соотношение «присадка = 100 × ДТ» |
| Модельный сценарий блендинга | эксперт подтвердил допустимость; состав резервуаров в `config/scenarios.yaml` |
| Отклик цетанового числа на присадку | кусочно-линейный с насыщением, поведение 2-этилгексилнитрата |
| Масштабы тегов историка (F15/2000, F25/200, P8×2000, F19×0.02) | выведены из исправления эксперта и сверки с ЛИМС; на критическом пути не используются — температура реактора берётся по T5 в °C напрямую |

Что **не** допущение: формулы ВАК (даны экспертом), задержка ЛИМС 4 ч (дана
экспертом), сентинел 307 (дан экспертом), спецификации по сере, плотности и
цетановому числу (даны экспертом), управляющие переменные гидроочистки
(названы экспертом).

## Что бы мы сделали следующим шагом

1. **Активная идентификация.** Главное ограничение — не алгоритм, а данные:
   в истории нет управляемых возмущений. Серия коротких плановых ступенек по
   температуре (±1 °C, 4 часа) даст усиления с доверительными интервалами и
   снимет необходимость в литературном приоре.
2. **Сличение лаборатории и поточного анализатора.** Половина разброса —
   измерительная. Программа сличения по ГОСТ ISO 4259 окупится быстрее, чем
   любое улучшение модели.
3. **Замкнутый контур.** Сейчас система советует. Переход к записи уставок
   требует контроля скорости изменения, watchdog и отработанной процедуры
   передачи управления оператору.
